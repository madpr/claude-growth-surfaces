Bonus · alongside the three-idea slate

Who is paying for this session?

Claude Code resolves which credential pays — subscription login, environment variable, on-disk config — without surfacing the decision or the reason for it. An application credential is being read as a tooling authorization.

This is a bonus, not one of the three ideas. It is scoped to Claude Code rather than the API product, and its direct effect is to move revenue off the API and onto subscriptions. The trust and churn case for it is real but second-order. It is here because it is the one piece of this submission that survived verification — a defect reproduced on the current build, a corpus of real reports, and a prototype that runs.

The defect

The diagnostic surface reports the same answer in both states

The documented way to check which credential is paying is /status, or claude auth status. On the current build, setting ANTHROPIC_API_KEY displaces an active subscription while both authMethod and apiProvider continue to report the subscription path. The only signal that anything changed is a field going null.

$ claude auth status --json | jq -c '{authMethod,apiProvider,subscriptionType}' {"authMethod":"claude.ai","apiProvider":"firstParty","subscriptionType":"pro"} $ ANTHROPIC_API_KEY=sk-ant-… claude auth status --json | jq -c '…' {"authMethod":"claude.ai","apiProvider":"firstParty","subscriptionType":null}

Reproduced 3/3 on v2.1.252. ANTHROPIC_AUTH_TOKEN at least relabels to oauth_token; an empty-string key is correctly ignored. ANTHROPIC_API_KEY is the one credential that displaces silently.

This is not a bug report. The behavior is documented as intended — support guidance is “keep ANTHROPIC_API_KEY unset.” The argument is that the default is wrong: an env var set for the app a developer is building should not silently decide how their editor is billed.

The thesis

Unpriced uncertainty suppresses usage — but what’s unpriced isn’t dollars

Every approval prompt in an agentic session is a bet the user cannot price, so they bet small: shorter sessions, fewer autonomous runs, more manual review. The ceiling on agentic usage is nerve, not capability.

The obvious reading — that the nerve is about money — does not survive contact with the product. Anthropic already sells a plan where the marginal cost of one more tool call is exactly zero. Max subscribers still babysit their runs. The thing users cannot price is whether the run will be allowed to finish.

API user

A cost I can’t explain afterwards.

Subscriber

The five-hour window closing at minute thirty, mid-task.

Enterprise

A budget someone else owns, with no per-team attribution.

Same anxiety, three currencies. The subscription case is the worst of them: you cannot pay your way past a window reset. This is also why the fix is not a meter — a meter answers a question only one of these three users is asking.

The prototype

Detecting displacement, not just reporting auth

Because authMethod reports the same value either way, the indicator cannot simply read it. It probes twice — once as the environment stands, once with the credential variables stripped — and compares. The difference between them is an entitlement that exists and is not being spent.

# what this environment resolved resolved=$(claude auth status --json) # what it would resolve without the credential vars latent=$(env -u ANTHROPIC_API_KEY -u ANTHROPIC_AUTH_TOKEN \ claude auth status --json) # a subscription that exists but is not paying = displacement [ -z "$resolved_sub" ] && [ -n "$latent_sub" ] && state=CONFLICT

The third state matters as much as the first two. A developer with an API key and no subscription is being billed correctly, and gets no warning — the indicator stays quiet when the behavior is right.

── subscription pays ───────────────────────── ◆ PRO SUB · Opus ████░░░░░░ 41% · 5h 62% · caps in ~23min ── env var displaced a subscription ────────── ▲ API KEY ····4f2a · Opus ANTHROPIC_API_KEY displaced your pro subscription ── API key, no subscription: correct, silent ─ ◇ API KEY ····test · Opus ████░░░░░░ 41% · $2.14

Roughly 180 lines of bash against the documented status-line contract. The auth probe costs ~210 ms, so it is cached for 30 s and keyed on a fingerprint of the credential variables — changing one invalidates the cache immediately. Rendered output: 68 ms.

The rate_limits object in the status-line payload carries five_hour.used_percentage and resets_at alongside cost.total_cost_usd. Both currencies of the thesis are already on the wire. The continuity projection above — caps in ~23min — is computed from them, not mocked.

Scope

How far this could go

Three depths for this one idea — not the three ideas of the slate. Each is a stopping point that stands on its own.

S

Attribution, pushed rather than pulled

Name the paying credential at session start and keep it visible. When an entitlement was displaced, say so and offer the switch. The information already exists — it is reachable only by a user who has already become suspicious, which is the wrong precondition.

Measures: share of subscription-entitled sessions running on API credentials; support contacts about unexpected charges.

M

The continuity contract

Headroom before a long run, live burn against it, and a cap that pauses with a one-key raise instead of terminating. The primitive already ships: --max-budget-usd exists, is print-mode only, and #85400 reports it killing a Max-subscription run at Total cost: $0.0000 with quota remaining. Fixing a broken cap is a smaller ask than proposing one, and it avoids the anchoring risk — a low limit set once and never revisited turns a soft anxiety into a hard ceiling.

Measures: autonomous run length; declined tool calls per session; user-initiated aborts.

L

Org-level spend attribution

Per-team and per-repo budgets, forecasting, chargeback — and a fix for costs being computed at list price, so figures shown to organizations on contracted rates do not match their invoice. This is the tier where the thesis is unambiguously true: the person carrying the anxiety is the person who signs the rollout, and their uncertainty blocks deployment rather than usage.

Measures: pilot-to-rollout conversion; seat expansion rate.

The weakness worth naming first. Cost anxiety is highest where revenue is lowest — a solo developer on a personal key — and lowest where revenue is highest, on an enterprise seat where the organization pays and the developer feels nothing. S and M address the loudest users; L addresses the largest ones. Any pitch that does not say so is waiting to be caught.

Falsification

What would kill this

  • The thesis: if Max session lengths match API session lengths after normalizing for task type, cost uncertainty is not the constraint and only S survives on trust grounds alone.
  • The S tier: if the share of subscription-entitled sessions running on API credentials is under about one percent, this is a support problem, not a growth surface. That single query decides it, and I cannot run it from outside.
  • The M tier: if declined tool calls do not fall once headroom is visible, the hesitation was about blast radius rather than exhaustion — which is a real possibility, and a different and probably larger piece of work.
