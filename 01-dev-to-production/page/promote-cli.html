Design mock · dev to production

Promote from Claude Code

The developer never leaves the tool they are already in. Claude Code reads the project, says plainly what will not survive the move, and proposes a sandbox that replaces it. The browser finishes the job, because the account boundary forces a handoff.

1

Answer the question a developer actually asks

Today claude agents means background sessions on your laptop, and that is the whole discovery failure: the word is spent on a local answer, so nobody learns the hosted surface exists. The cheapest version of this proposal is this screen alone.

$ claude agents ON THIS MACHINE ● 2 running claude attach <id> reconcile-nightly 12m waiting on tests docs-sweep 4h idle HOSTED runs when you are not here ○ none yet claude promote

Both halves of the word, in one place. The hosted row is the addition.

2

Read the project, and be honest about the total

Most of a hosted agent already exists on disk. The interesting number is not what carried over — it is the two lines under it.

$ claude promote ledger-reconcile · nightly revenue reconciliation ✓ carries over model, instructions, tools, 1 skill, 1 service ● needs you what this agent is for, in one line ● does not carry 3 rules, 1 local service

Counts come from the prototype's own output against its sample project.

3

Translate the rules, and admit the residue

This is the moment the whole proposal turns on. The rules a developer wrote to keep an agent in its lane are exactly the part that cannot travel, and a hosted sandbox starts with none of them. Showing this as an error would be wrong: it is not a failure of the import, it is the job of the screen.

Three rules keep this agent in its lane on your machine. A hosted sandbox enforces none of them. deny Write(ledger/**) → mount ledger/ read-only deny Bash(rm *) → nothing to protect: the sandbox is discarded after every run allow Bash(python3 reconcile.py *) → no equivalent. The sandbox runs any command. Narrow it in the image, or accept it. mcp local-fs-index → runs from your machine. Publish it as an endpoint, or drop it. ● Two are proposed above. Edit, accept, or set your own.

Two of four translate. One has no equivalent and one has to be rebuilt. A screen that pretended every rule mapped cleanly would be lying, and the developer would find out on the first unattended run.

4

Set the cap now, because there is no later

A spend cap can only be set when a run is created. A run started without one can be killed, but never capped. That makes this screen the only chance, so it says so rather than offering an optional field.

Spend cap $ 25.00 per run A run started without a cap can be killed, but never capped. This is the only time it can be set. Schedule __________ CLAUDE.md says “every night”. That is not a time. This creates an agent, a sandbox and a schedule in your platform organization — not the account signed in here. → open browser to confirm ↵

The handoff is not a convenience. On the account this was built from, Claude Code and the platform resolved to two different organizations, so confirming in the browser is where the developer signs in to the one that will own the agent.

What is real and what is proposed

  • Verified against the installed binaries
  • Proposed — does not exist today

Real. claude agents exists and means background sessions. claude attach takes the short id it prints. Spend caps are create-only on a hosted run. Hosted agents connect to services over a URL, so a server started locally has no hosted form. Claude Code and the platform CLI sign in to separate organizations. Captured from Claude Code 2.1.259 and the platform CLI 1.29.0 on 3 September 2026.

Proposed. claude promote, the hosted row in claude agents, the rule translations, and the browser handoff. None of it ships.

Where the numbers come from. The three totals in step 2 and all four rules in step 3 are produced by prototype/promote.py against prototype/fixtures/sample-project, so the mock and the code cannot disagree. The project shown is that fixture, not a real account.

The spend cap and the running background sessions are example values, filled in the way a person would fill them. The schedule is deliberately empty: the fixture says the job runs “every night”, which is not a time, and the prototype emits no schedule at all. A flow that guessed one here would be inventing the developer's intent at the last moment before the agent runs unwatched.
